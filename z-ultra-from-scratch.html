Modular Architecture: Complete Wipe & Decoupled App Slot

Total separation between permanent hardware device drivers and replaceable userland applications.

Snapdragon 800 Drivers & Kernel

MSM8974 kernel modules, Qualcomm WCN3680 Wi-Fi prima firmware, High-Speed UART (/dev/ttyHS0), NXP PN544 I2C NFC (/dev/pn544), InvenSense MPU6500 IIO motion sensors, and MDM9225 baseband modem.

Alpine Linux 3.20 (/data/alpine)

Boot-to-App Screen Only: Direct Framebuffer Kiosk

How the phone boots straight into the application screen in ~3 seconds with zero Android UI.

Kiosk Mode Active
How It Works: Zero Android UI Overhead

When the Xperia Z Ultra powers on, the bootloader loads the downstream kernel. Instead of launching the heavyweight Android framework (SurfaceFlinger, SystemServer, Zygote, Lockscreen), our boot sequencer:

  • Hardware Display Wake: Wakes the MIPI DSI controller via echo 0 > /sys/class/graphics/fb0/blank and sets panel backlight to comfortable brightness.
  • Android SurfaceFlinger Suppression: Signals Android init to stop display server daemons so the direct framebuffer (/dev/graphics/fb0) has zero contention.
  • Direct Framebuffer Binding: The modular app renders directly to raw 1080×1920 32-bit ARGB video memory using zero-copy memory mapping.
  • Supervisor Respawn Watchdog: kiosk_autostart.sh monitors the application process. If an unhandled exception or crash occurs, it respawns in under 1 second. The screen never drops to a console or black screen.
Boot-to-Screen Flow
1. Phone Power-On → Kernel Boot
2. /data/start-alpine.sh invoked
3. Unblank /dev/graphics/fb0
4. Launch /opt/app/entrypoint.sh
✓ Fullscreen App Screen Active
✓ Elapsed Boot Time: ~3.2s

Third-Party App Lifecycle: Wipe, Install, Hot-Swap

How any developer can build, deploy, wipe, or replace an app in /opt/app without affecting device drivers.

Open Application Standard
The Modular Application Contract

A modular app package is simply a directory or .tar.gz archive placed in /opt/app (host path: /data/modular-app) containing a standard manifest and executable entrypoints:

Required App Bundle Structure: 
my_custom_app.tar.gz
├── manifest.json       # App metadata & hardware nodes
├── entrypoint.sh       # Executable entrypoint
├── install.sh          # Optional dependency setup hook
└── src/                # Your Python, C, Go, or Rust code
manifest.json Schema: 
{
  "name": "my-custom-kiosk",
  "version": "1.0.0",
  "author": "Third Party Developer",
  "runtime": "python3",
  "entrypoint": "entrypoint.sh",
  "target_arch": "armv7l"
}
modular-app-mgr Command Reference:
Command Action Effect on Base System & Drivers
modular-app-mgr wipe Erases /opt/app completely and halts running app Zero Impact Base drivers, SSH, network, & kernel remain untouched
modular-app-mgr install <pkg> Wipes old app, extracts new payload into /opt/app, runs install.sh Zero Impact Fresh app installed cleanly into isolated slot
modular-app-mgr start Launches app in background supervised by watchdog Supervised Automatically respawns if app exits
modular-app-mgr stop Gracefully shuts down running application Safe Stop Releases framebuffer and hardware devices
modular-app-mgr status Inspects running PID, memory usage, and manifest.json Diagnostic Real-time telemetry report
